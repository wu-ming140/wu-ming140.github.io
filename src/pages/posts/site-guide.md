这是一份留给自己、也留给第一次来到这里的朋友的小站说明书。操作和入口以 2026 年 11 月 1 日这一版为准，后面有调整时再继续补充。

如果只想快速发布一篇文章，可以直接看“用写作台发布一篇文章”；如果要整理提问、设置置顶或加入合集，可以通过旁边的目录跳到对应部分。

## 用写作台发布一篇文章

### 第一步：填写基本信息

1. 打开[写作台](/studio/)，选择“文章 / 作品集”。
2. 保留自动生成的文件名，或改成没有使用过的小写英文、数字和连字符组合，例如 `my-first-project`。
3. 填写标题、日期，并选择专栏。发布作品时选择“作品集”。
4. 补上一句话简介和标签。多个标签用逗号分隔，最多 12 个，每个最多 32 个字。
5. 在正文框中写内容，通过旁边的预览确认效果。

正文可以使用 Markdown：用 `## 标题` 分章节，用 `### 小标题` 细分内容，发布后会生成文章目录。普通文字、列表、引用、代码块和链接也可以直接写。

文件名会影响内容地址。新建时取好名字，编辑已有内容时保留原文件名，方便继续使用原来的链接。

### 第二步：选择封面、插入图片与视频

文章和作品可以点击“选择封面图片”，也可以填写已有图片的站内路径或外部网址。封面会出现在正文前，作品集还会用它生成展示卡片；填写“封面说明”方便理解图片内容。

正文媒体有几种插入方式：

- 点击“插入图片 / 视频”，选择本机文件。
- 把图片、视频拖到正文框，或粘贴截图。
- 点击“插入媒体网址”，填写说明和媒体文件的完整网址。

选择的媒体会插入光标所在的位置。图片可以点击放大；视频显示播放器。封面无需再重复插入正文，清空封面地址即可取消封面。

写作台支持 PNG、JPG、JPEG、GIF、WebP、AVIF 图片，以及 MP4、WebM、OGV 视频。单个文件不超过 20 MB，当前附件总计不超过 50 MB。

外部视频需要能直接打开视频文件的地址。B 站等平台的普通播放页面请作为普通链接放进正文。

### 第三步：检查并选择发布方式

先点击“发布前检查”，根据提示补齐信息，再选择适合自己的方式。

**方式一：下载草稿，在电脑上发布。** 点击“下载完整草稿”，得到正文和本次所用新附件组成的 ZIP。解压到本地博客根文件夹，确认文件后，在 GitHub Desktop 提交并推送到 `main`，等待网站自动更新。草稿包不会重复下载仓库里已有的旧附件。

**方式二：连接仓库，在网页发布。** 展开“连接 GitHub，直接发布”，使用页面里的“创建专用凭证”入口，选择当前博客仓库，按页面提示将 Contents 权限设置为 Read and write。粘贴凭证后点击“连接我的仓库”，再点击“发布到博客”，核对检查结果、标题与附件数量，最后点击“确认发布”。

凭证只用于当前页面连接，刷新后需要重新输入。不要把它写进正文。发布成功表示内容已保存到仓库，正式网站还需要等待部署完成；可以通过“查看网站发布进度”查看结果。

通过网页发布后，电脑上的仓库先拉取更新，再继续本地编辑。

## 草稿怎样保存，旧文章怎样修改

### 本机草稿与恢复

写作台会自动保存当前文字、栏目设置和所选图片、视频，页面会显示保存状态。刷新或重新打开后，会恢复这份本机草稿；无需先连接 GitHub。

同一浏览器、同一网站地址只保留一份当前草稿。“新建内容”或“载入编辑”会替换它，需要保留多份时，请分别下载完整草稿包。本地预览和正式网站的草稿各自独立，也不会自动同步到另一台设备。

清理浏览器的网站数据会清除本机草稿。保存失败或多个写作台发生冲突时，按页面提示先下载备份。发布成功后，本机待恢复草稿会清除。

### 编辑已发布内容

1. 连接仓库。
2. 在“编辑已有内容”中选择文章、留言、提问或回复，点击“载入编辑”。
3. 修改正文、封面、标签或整理设置。
4. 再次检查、发布。

已有文件名会保留，旧链接和回复关联继续使用。移除正文里的图片或视频，不会自动删除仓库中的原文件。

如果仓库在编辑期间有了其他提交，写作台会拒绝覆盖。先下载当前草稿，再重新连接、载入最新内容后整理发布。

## 留言、站外提问和回答怎么写

### 博主自己的留言

在写作台选择“我的留言”，填写标题、日期、昵称、来源和正文。来源可以写“博主自留”，也可以按实际情况填写。这类手动录入的留言会进入留言区和“其他渠道来信”。

### 整理其他渠道的提问

1. 内容类型选择“其他渠道的提问”。
2. 填写标题、日期、提问者愿意公开的昵称和来源，例如微信、QQ、邮件。
3. 在正文中手动整理问题，检查后发布。
4. 记下这条问题的文件名，后面回复时使用。

这里由博主手动录入，不会连接或自动读取其他平台的聊天记录。

### 给问题写回答

选择“博主回复”，新建一个回复文件。在“回复哪条留言”里填写对应问题或留言的文件名，不含 `.md`，再填写日期和回答正文。

例如，问题文件叫 `2026-11-01-wechat-01.md`，回复关联处填写 `2026-11-01-wechat-01`。先发布问题，再发布回复；回复日期不能早于问题日期。

同一问题可以添加多份回复，网站会按日期排列。提问有公开回复后会显示“已回答”，也会离开“待回答”列表。

留言、提问和回复可以勾选“先保存为草稿”，暂不进入公开列表。文章在写作台中尚未发布的编辑也只保存在本机；若在电脑里给文章写 `draft: true`，它会从公开列表、搜索、合集和订阅中排除，但这不等于给文章网址加上访问权限，不适合保存私密内容。

### 访客怎样给小站留言

访客可以进入[写留言 / 提问](/guestbook/contribute/)，按页面说明使用 GitHub 模板提交来信，发起合并请求，待博主审核合并后展示。

写作台的直接发布功能供拥有仓库写入权限的博主使用。通过其他渠道收到的提问，由博主在上面的流程里整理。

## 怎样设置和取消置顶、精选

新建或载入文章、留言、提问后，在写作台的“置顶与精选”区域，按目标板块分别勾选。

| 内容类型 | 可以独立设置的范围 |
| --- | --- |
| 文章 / 作品 | 大厅、当前所属专栏 |
| 留言 | 全部来信、留言；其他渠道内容还可设置其他渠道来信 |
| 提问 | 全部来信、提问、待回答；其他渠道内容还可设置其他渠道来信 |

各板块分别显示“本板块置顶”和“本板块精选”。例如，只勾选学习专栏置顶，不会自动成为大厅置顶；普通列表仍保留这份内容。

**取消方法：** 载入内容，取消对应勾选，或点击“清除此板块标记”，再重新发布。只清除这个板块，其他板块的设置不受影响。没有相应内容时，栏目会自动隐藏。

文章改换专栏时，旧专栏的标记不会自动迁移到新专栏，需要在新专栏重新选择。提问已有公开回复时，不再显示在待回答栏目。

## 怎样创建、排序和退出合集

在写作台的“加入合集”中填写合集名称和顺序号。不同内容使用同一个名称，就会自动组成一个合集。

比如，先后把三份内容加入“我的第一个项目”，顺序号分别填写 1、2、3，就可以按“想法 → 制作过程 → 成果展示”连续阅读。

合集可以跨专栏，也可以混合收录文章、留言和提问。一份内容最多加入 12 个合集；点击“再加入一个合集”即可增加。

顺序号使用 1–99999 的整数，不要求连续。同号内容再按日期、地址排序；发布前检查会提示重复顺序号。想调整顺序，载入对应内容修改顺序号后发布即可。

要退出某个合集，点击这一行的“移出合集”并重新发布。移出不会删除内容，也不会影响其他成员。最后一份成员移出后，空合集会从列表消失。

导航栏“合集”可以查看所有合集。内容底部会显示所属合集、当前阅读位置和合集上一项、下一项。普通上一篇、下一篇则按日期排列：文章与作品之间连续阅读，留言和提问分别按类型排列。

## 怎样筛选、搜索和按年月浏览

大厅、各专栏、留言及其他渠道来信的“浏览方式”提供三个选择：最新在前、最早在前、按年月归档。

默认使用普通列表。选择“按年月归档”后才按月份分组，随时可以切回。排序不会改变独立的置顶、精选栏目。

留言区还可以按全部、留言、提问、待回答或其他渠道筛选；筛选和月份归档可以一起使用，没有内容的月份会隐藏。

站内搜索支持标题、简介、正文、专栏和标签，也包括公开来信与公开回复。多个关键词用空格隔开，可以继续按内容类型筛选。标签页适合查同一主题的文章；文章目录适合在长文里快速跳转。

## 怎样看浏览量和订阅更新

大厅与页脚显示全站总浏览量，文章标题下显示该篇阅读次数。浏览量按访问次数记录，不等于独立访客人数，接入前的历史访问无法补记。

本地地址显示“预览不计数”是正常状态。正式网站显示“暂不可用”时，表示统计服务或网络暂时没有返回有效结果；可稍后刷新，不能把这个状态当作真实的零次浏览。

打开[RSS 订阅](/subscribe/)，按需要选择全站动态、文章与作品，或留言与问答，复制地址到自己的 RSS 阅读器。每份源保留最近 50 项公开内容。

留言订阅会带上公开回复的摘要；旧来信新增回答是否提醒，取决于阅读器的处理方式。本机草稿和未公开内容不进入订阅。

## 发布前检查会检查什么

写作台里的“发布前检查”可随时手动运行，正式发布时也会再次执行。

| 提示 | 怎么处理 |
| --- | --- |
| 需要修改 | 修正后再发布，例如缺少必要内容、站内媒体文件不存在、回复找不到对应留言或日期不合法 |
| 建议检查 | 核对后决定，例如缺少简介、作品封面、媒体说明、未来日期或合集顺序号重复 |
| 提示 | 了解当前状态，例如未连接仓库暂时不能核对旧媒体、设为草稿或附件未被使用 |
| 通过 | 当前检查未发现需要处理的问题，可以继续核对预览 |

未连接仓库时，仍能检查必要字段与内容格式；已有站内媒体文件是否存在，要连接后才能核对。外部网址不会逐个自动访问，请自己在预览中检查。

## 在电脑里直接编辑的写法

文章放在 `src/pages/posts/`，也可以复制仓库中的 `templates/post.md` 作为起点。下面是一份属于“小站日志”的文章示例：

```markdown
---
layout: ../../layouts/PostLayout.astro
title: "我的一次小站更新"
description: "记录这次改动和使用感受。"
pubDate: "2026-11-01"
category: "小站日志"
tags: ["小站日志", "功能更新"]
---

## 这次改了什么

在这里写正文。
```

图片和视频文件放入 `public/media/`，正文地址省略 `public`。例如：

```markdown
![首页截图](/media/my-project/home.png)

![作品演示](/media/my-project/demo.mp4)
```

以下设置加在文章开头的两条 `---` 之间，可以让它在小站日志专栏置顶，并加入一个合集：

```yaml
placements:
  site-log:
    pinned: true
collections:
  - name: "小站搭建记录"
    order: 1
```

站外问题放在 `src/content/guestbook/`，博主回复放在 `src/content/replies/`。对应模板可以在 `templates/` 中找到。只改内容时，通常不需要改页面代码。

在博客根文件夹运行 `npm run dev` 可以本地预览。提交前运行 `npm test` 和 `npm run build`，检查通过后提交并推送，等待网站部署完成。

## 常见情况速查

| 遇到的情况 | 可以这样处理 |
| --- | --- |
| 写了内容，正式网站还没变化 | 确认已发布或推送，再查看部署进度；只保存在本机的草稿不会公开 |
| 取消置顶后还看得到 | 确认改的是目标板块，并重新发布；其他板块的标记分别管理 |
| 页面没显示置顶、精选栏目 | 该板块需要至少一份已公开且有对应标记的内容 |
| 视频无法播放 | 检查是否为媒体文件直链，以及当前浏览器是否支持该视频编码 |
| 图片、视频发布检查报缺失 | 选入本机文件一起发布，或修正为仓库中真实存在的站内路径 |
| 网页发布提示仓库已有更新 | 下载当前草稿备份，重新连接、载入最新版本再整理 |
| 刷新后需要重新连接 | 发布凭证只留在当前页面内存中，这是现有连接方式的正常行为 |
| 合集里没出现内容 | 核对名称是否相同、内容是否已公开，以及改动是否已发布 |

这轮功能的整体变化，另外记录在[《小站更新日志：把文字、来信和作品安放好》](/posts/2026-11-01-site-update/)中。日常忘记操作时，就从这份说明书的目录里找对应部分。
