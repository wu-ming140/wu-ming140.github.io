static静态成员
加了static     表示不属于任何对象  就没有Outer.this
```
class Outer {
    int count = 10;   // 注意：没加 static
}
```
没加 `static`，意思是**每一个 Outer 对象都有自己的一份 count**。
造两个对象：
```
Outer o1 = new Outer();
o1.count = 10;

Outer o2 = new Outer();
o2.count = 20;
```
内存里：
```
o1 ──→ [ count = 10 ]
o2 ──→ [ count = 20 ]
```
两份，互不相关
```
static class Inner {
    void hi() {
        System.out.println(count);  
    }
}
```

打印 `count`，得先知道一件事：**是 o1 的 count，还是 o2 的 count？**
如果不知道，这行就没法执行。
就像写 `brand` 之前必须先有 `p1`   `System.out.println(brand)` 单独这么写在类里
编译器也会拦你：你问哪个对象的 brand？
```
class Outer {
    int count = 10;
    class Inner {               // 注意：没有 static
        void hi() { System.out.println(count); }   // ✅ 能
    }
}
```
为什么这里inner能打印  
因为**这种内部类的每个对象里，都偷偷存了一个“我属于哪个 Outer 对象”的引用**，也就是 `Outer.this`。

`new Outer().new Inner()` 的时候，已经先造了一个 Outer 对象，Inner 就记住它了。所以 `count` 就是那个 Outer 的 count


**加了 `static`，工牌没了**
```
static class Inner {            // 注意：有 static
    void hi() { System.out.println(count); }   // ❌
}
```
`static` 的含义就是 **“我不属于任何对象”**。既然不属于任何对象，就没有 `Outer.this`
```
无法从静态上下文中引用非静态变量 count
```
**“静态上下文”就是“没有对象的场合”**。这句话翻译过来就是：
> 你在一个没有对象的地方，去用一个必须有对象才能用的变量。

顺带说明，`static` 方法里不能用 `this`

如果想要用count   在加了static的inner类里用
那要在count前也加static    让他不需要对象
~~~
class Outer{
	static int count=10;
		static class Inner{
			void hi()
			{
				System.out.println(count);
			}
		}

}

~~~

另一种方法是直接把class的Outer对象代入
~~~
class Outer{
	int count=10;
	static class Innerz{
		void hi(Outer o)//类似传入参数  
		{
			System.out.println(o.count);
		}
	
	}
}

~~~

## 匿名内部类  lambda
**匿名内部类     省略起名字**
~~~
class Keyboard implements USB {
    public void work() { System.out.println("键盘输入"); }
}

USB u = new Keyboard();
~~~
Keyboard只用依次  专门起名字    浪费
java可以这样写：
~~~
USB u=new USB()//   new USB()  要实现USB这个接口   括号空表示接口没有构造方法  不传参数
{//没有名字的类的类体  照常写方法
	public void work()
	{
		System.out.println("键盘输入");
	}
};//这个USB没有类名   还要加分号

//整串代码是赋值语句   要分号
~~~
代码块：定义一个没名字的类（implements USB）  +  立刻 new 一个对象

`new USB()` 看着像“new 了一个接口”，其实不是。
接口照样不能 new，**真正被 new 的是那个匿名的实现类**。
“接口不能 new”  没错     只是这里看不见类名。

**它没有名字，所以不能写构造方法，也没法再次 `new` 它**。它就是一次性的

接口里声明的函数一定要在之后具体实现

**练习：综合   把匿名内部类当作参数直接传     这是最好用的时候**
~~~
interface USB{
	void work();
}

public class study01{
	static void arr(USB device)
	{
		//参数这里传接口的类型
		device.work();
	}
	
	public static void main(String[] args)
	{
		arr(new USB(){
			public void main()
			{
				System.out.println("键盘录入");
			//直接把对象塞入参数   就是上面的USB u=new USB(){};
			}
		})
	}

}
~~~


`new USB(){...}` 整块本身就是一个对象，直接当实参传进去了。

`arr` 的参数类型是 `USB`，传进去的是「实现了 USB 的匿名类对象」，所以能传
**这就是向上转型，还是多态那一套**。匿名类只是个没名字的实现类。

**可以再省去一些字    就是接下来的lambda**
~~~
USB u=() -> System.out.println("键盘录入");
~~~
**方法签名可以整段不要**

对应：
```
USB u = new USB() {                 // ┐
    public void work() {            // │ 这三行全没了
    System.out.println("键盘输入");   // ┘ ← 只剩这句
    }
};                            // 剩下来的形状是：() -> 这句
```
拆开看三块：
- **`()`**：就是 `work()` 的括号——参数列表。`work()` 没有参数，所以括号里空着。
- **`->`**：读作“去做”。
- **右边**：方法体。只有一句，所以 `{ }` 都省了。

Lambda只能用在  函数式接口
接口里只有一个抽象方法  就叫函数式接口
得知道 `()` 和 `->` 中间这段代码，到底是在实现**哪个**方法。只有一个抽象方法，那就不必猜——不用写名字也认得出

**带参数的lambda**
~~~
interface calculator{
	int add(int a,int b);
}

calculator c=(a,b)-> a+b;

System.out.println(c.add(1,2));

~~~
两个抽象方法就不是函数式接口了，`()` 和 `->` 没法说明自己在实现哪一个
**Lambda 从头到尾没写方法名**


## 方法体不止一句时，`{ }` 
```
Calculator c = (a, b) -> {
    int sum = a + b;
    System.out.println("算了一下");
    return sum;                 // 有返回值的方法，必须 return
};
```
对比一下，一句话的版本 `(a, b) -> a + b` 其实等于：
```
(a, b) -> { return a + b; }
```
## 只有一个参数，连括号都能省
```
interface Printer { void print(String msg); }

Printer p1 = (msg) -> System.out.println(msg);   // 完整写法
Printer p2 = msg -> System.out.println(msg);     // 一个参数，括号可省
```
**没参数**就必须写 `()`（不能写成 `-> ...`），**两个以上参数**也必须写 `()`。


**完整代码练习**
~~~
import java.util.Scanner;


interface Printer{
	void print(String msg);
}


public class study01{
	public static void main(String[] args)
	{//用lambda打印msg
		
		Scanner input= new Scanner(System.in);   //   这里 new也是创建对象
		//或者说    new就是创建对象用的
		//包括说之前的东西都是
		//int[] a=new int[3];创建一个数组对象
		//  类型  变量名 = new 类型（参数）;
		//Scanner是java官方写好的一个类
		//System.in   是传给构造方法的参数  这里指  键盘（标准输入）
		//换成 new Scanner(new File("a.txt"))就是造一个读文件的扫描器。同一个类，参数不同，造出来的对象能力不同，这就是构造方法的作用。
		
		
		System.out.println("输入一句话");
		String text=input.nextLine();
		
		
		Printer p=msg ->System.out.println(msg);//用lambda具体化实现函数
		
		p.print(text);//这里也是个多态   p.print走的是lambda的实现
		
		input.close();
	}
}


~~~

如果把变量也起名 `msg`：
```
String msg = input.nextLine();
Printer p = msg -> System.out.println(msg);   // ❌ 编译错误
```

报错大意是 `variable msg is already defined`
**Lambda 的参数名，不能和外层已经存在的局部变量重名**。所以上面我用了 `m`，外层叫 `text`。
这条规则和“参数遮蔽成员变量”不一样：**成员变量可以被遮蔽，局部变量不行**



**关于变量input  补充学习**
变量input存的是  引用   不是对象本身
栈里：input ──→ 堆里：[ Scanner 对象 ]

`input` 只是一个“标签”或“遥控器”，对象在堆里。所以你写 `input.nextInt()`，实际是**通过遥控器操作那个对象**。

**和c++对照**

```
Student s;                                   // C++：对象直接建在栈上
Student* p = new Student();                  // C++：对象在堆上，p 是指针

Scanner input;                               // 如果 Java 也这么写……
```
Java **没有“栈上对象”这回事**。所有对象都在堆里，变量只存引用。所以 Java 里的 `Student s;` 只是“声明了一个能指向 Student 的标签”，**此时还没有对象**。

因此下面这样写是错的：
```
Scanner input;              // 只声明，没创建
input.nextInt();            // ❌ 编译错误：变量 input 可能尚未初始化
```

```
Scanner input = new Scanner(System.in);
//input存引用   这条执行完后堆里只有一个Scanner对象
```

## `==` 和 `equals` 的区别：用 C 对照

| Java          | C 里的对应                          |
| ------------- | ------------------------------- |
| `a == b`      | 比较**两个指针是不是同一个地址**，             |
| `a.equals(b)` | 相当于 `strcmp(a, b)`，比较**内容是否相同** |

在 Java 里：
- **基本类型**用 `==` 比较值，`int x == y` 比的是数字
- **引用类型**用 `==` 比较地址，即“是不是同一个对象”   

因此，要判断两个 `String` 的内容是否相同，**必须用 `equals`，不能用 `==`**。


~~~
String a = "abc";
String b = "abc";
String c = new String("abc");

System.out.println(a == b);        // true
System.out.println(a == c);        // false
System.out.println(a.equals(c));   // true
~~~
用双引号写出来的字符串会先被放入一个“字符串池”
~~~
String a = "abc";   // 池里没有 → 在池里造一个 "abc"，a 指向它
String b = "abc";   // 池里已经有一个 "abc" → 直接复用，不造新的
~~~
所以后面写`System.out.println(a==b);`  输出的是true
因为a和b指向同一个对象，所以是true

而 `new String("abc")` 里的 `new` 是强制执行“再创建一个对象”，**不管池里有没有**：
```
a ──→ 池里的 "abc"
b ──→ 池里的 "abc"      （和 a 是同一个）
c ──→ 堆里另一个 "abc"   （new 出来的，独立一份）
```

**比较内容只能用equal:   a.equal(b)比较a和b的值**
`==`只能用在“是不是同一个对象时的判断”    比如判断某个变量是不是null
~~~
if(name==null)
{
}
~~~
**只要有 `new`，就会创建新对象，地址必然不同。**
~~~
String c = new String("abc");

c == d        // ① false  —— 两个 new，两个不同的对象
c.equals(d)   // ② true   —— 内容都是 abc
~~~

**split   把字符串切成数组**
```
String s = "张三,20,北京";
```

## ArrayList   能自动加长的容器，动态数组？
~~~
ArrayList<String> list=new ArrayList<>();


list.add("张三");        // 尾部追加
list.add("李四");
list.add("王五");

System.out.println(list);                 // [张三, 李四, 王五]
System.out.println(list.size());          // 3      个数？
System.out.println(list.get(0));          // 张三   展示  拿到
System.out.println(list.contains("李四")); // true

list.set(0, "赵六");      // 改第 0 个
list.remove(0);           // 删第 0 个

~~~

**`ArrayList<String>` 里的 `<String>` 是“泛型”**，作用相当于声明“这个数组容器只装 `String` 类型”。如果往里 `add(123)`，会直接编译报错。
（`int` 这类基本类型不能直接写进尖括号，要写 `Integer`。这在学包装类时要细讲，这里先记住这条规则。）


**和数组对应**
数组：
```
int[] a = new int[3];     // 长度固定
a[0] = 10;                // 存
int x = a[0];             // 取
int n = a.length;         // 长度（字段，没括号）
```
ArrayList：
```
ArrayList<String> list = new ArrayList<>();  // 长度自动变
list.add("张三");           // 追加
String s = list.get(0);     // 取
int n = list.size();        // 长度（方法，有括号）
list.set(0, "李四");        // 改
list.remove(0);             // 删（数组没有这个操作）
```
- 数组中用 `a[0]` 取元素；ArrayList 用 `list.get(0)` 取元素，**不能用方括号**。

## C++ 对照

| C++                        | Java                |
| -------------------------- | ------------------- |
| `std::vector<std::string>` | `ArrayList<String>` |
| `v.push_back("张三")`        | `list.add("张三")`    |
| `v.size()`                 | `list.size()`       |
| `v[i]`                     | `list.get(i)`       |
| `v[i] = "李四"   （改`         | `list.set(i, "李四")` |
| `v.erase(v.begin())`       | `list.remove(0)`    |

用法几乎一样，只差三个词：`push_back` → `add`，`[]` → `get(i)` / `set(i, x)`。

Java 不支持运算符重载（`[]` 不能给自定义类型用），所以只能使用 `get` / `set` 方法。这里不是 Java 能力更弱，只是 Java 的选择不同。C++ 更自由，代价是 C++ 有不少概念需要额外解释，例如运算符重载。


## 遍历：两种写法都能用
```
// 普通 for：需要下标时用
for (int i = 0; i < list.size(); i++) {
    System.out.println(list.get(i));
}

// 增强 for：只是逐个读，更常用
for (String s : list) {
    System.out.println(s);
}
```
**数组用 `a.length`，ArrayList 用 `list.size()`**，在上面的普通 for 循环里，这个写法尤其容易写漏，因为两侧只差一对括号。
## 限制：尖括号里只能写“对象类型”
可以写：
```
ArrayList<String> list = new ArrayList<>();    // ✅
ArrayList<Integer> nums = new ArrayList<>();   // ✅
```
不能写：
```
ArrayList<int> nums = new ArrayList<>();
```

因为**集合是“装对象的容器”，而 `int` 是基本类型，不是对象**。Java 规定泛型里只能放引用类型。
所以装整数要用 `Integer`——它是 `int` 的“包装类”。`String` 同理，它本来就是类
Java 里“基本类型”和“引用类型”是两套体系，集合只认后者。**包装类就是这座桥。**


如果写：
~~~
ArrayList<Integer> nums = new ArrayList<>();
nums.add(1);      // 1 是 int，不是对象
System.out.println(nums.get(0));
~~~
java会把1变成Integer类型
叫**装箱**    还有拆箱

~~~
Integer a = 10;      // 装箱：int 的 10  → Integer 对象
int b = a;           // 拆箱：Integer 对象 → int
~~~


编译器会自动把“基本类型”和“包装类”来回转换。手动写法是这样：
```
Integer a = Integer.valueOf(10);   // 显式装箱
int b = a.intValue();              // 显式拆箱
```
**自动装箱，就是编译器 `10` 悄悄换成了 `Integer.valueOf(10)`。**

## 为什么非要这层转换？
因为**集合只能装对象**。还没有包装类时，`ArrayList` 就无法存放整数。有了 `Integer` 这个“壳”，`int` 才能被装进集合中。因此，包装类的作用是让基本类型能够转换为对象。

对照 C++：`std::vector<int>` 直接就能存 `int`，压根没这回事。**这是 Java 泛型的限制**
学集合会更明显感觉到。


```
Integer a = null;
int b = a;
```
拆箱动作是：
```
int b = a.intValue();    // 编译器偷偷这么干
```
`a` 是 `null`，还对它调用方法，就相当于“对着空气调用 `intValue()`”，于是 JVM 抛出空指针异常。


对于int  基本类型     不能是null    默认值是0
对于Integer   包装类   可以是null  默认是null  此时只要一拆箱就会炸。所以包装类使用前不能是null

**这也是为什么“基本类型”和“包装类”不能随便混用**：`int` 是“一定有值”，`Integer` 是“可能没有值”。这个区别在数据库、JSON 里天天出现——查不到数据时，返回的就是 `null`。


**对于“可能没有值的，没有登记的”用包装类   有值的用基本类型**



对于常用API   剩下的 `BigDecimal`（精确小数、算钱）、日期时间、`Objects`、`Math`，都是**独立的工具类**，用到再学不迟

**`List` 和 `Set` 最直观的差别是“能不能重复”**

~~~
import java.util.ArrayList;
import java.util.HashSet;

public class study01{
	public static void main(String[] args)
	{
		ArrayList<String> list = new ArrayList<>();
		list.add("张三");
		list.add("李四");
		System.out.println(list.size());   //   2  重复也算
		
		HashSet<String> set = new HashSet<>();
		set.add("张三");
		set.add("张三"); //重复的时候  不报错也没有加进去  只是返回false  然后不处理了
		
		
		
		set.add("李四");
		System.out.println(set.size());   //  2  第二个张三没了  重复的进不去
		
	}

}
~~~
注意：**`HashSet` 打印出来的顺序是不固定的**。你不要指望它按添加顺序排，那是 `LinkedHashSet` 干的事。


**关于HashSet的add   是先判断原集合是否已经存在   然后再根据结果返回
如果存在就返回false 然后跳过    如果没有就放进去   返回true**

**全程不报错。** `List` 的行为是“来者不拒，重复也收”，`Set` 的行为是“重复的东西不收，也不告诉你”。


## 靠什么判断“重复”
靠 `equals`。也就是说，**它用内容判断两个对象是否相等**，而不是地址。

这也解释了为什么 `String` 能去重：`String` 已经正确实现了 `equals`。

（这点先记下来：等学到 `HashMap` 原理时，会详细讨论 `hashCode` 和 `equals`，那是集合章的核心。现在只要知道**去重靠 `equals`** 就够。）

## 一个和 C++ 不同的地方
C++ 里：
```
std::unordered_map<std::string, int> m;
int x = m["王五"];      // 不存在 → C++ 会自动插入一个 0
```
Java 里：
```
scores.get("王五")      // 不存在 → 返回 null，不会自动插入
```
**C++ 的 `[]` 会“顺手创建”，Java 的 `get` 只查询、不创造。**

## 有个坑
```
Integer v = scores.get("王五");   // null
int x = v + 1;                    // ❌ 运行时 NullPointerException
```
Integer` 是 `null`，一拆箱就炸。 这行 `v + 1` 要先拆箱，直接 NPE。

所以 Map 的常规写法是**先判断、再取值**：
```
if (scores.containsKey("王五")) {
    int v = scores.get("王五");
}
```
