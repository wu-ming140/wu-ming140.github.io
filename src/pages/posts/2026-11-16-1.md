## 抽象类 构造方法 子类实现串联实践

**抽象类不能直接创建对象，但可以有构造方法**

比如动物都有名字，但具体怎么吃，由子类决定
~~~java

//抽象类  动物整体
abstract class animal{
	private String name;
	public animal(String name)
	{
		this.name=name;
	}
	
	public String getname()
	{//构造方法   初始化姓名
		return name;
	}
	public abstract void eat();
	//抽象方法  声明“行为”  具体实现到子类那边
	//抽象方法没有{}
}

//狗
class dog extends animal{
	public dog(String name)
	{
		super(name);//调用父类的构造方法，初始化名字
	}
	
	@Override
	public void eat()
	{//重写eat  补具体实现
		System.out.println(getname()+"在吃狗粮");
	}
}


public class study01{
	public static void main(String[] args)
	{
		animal a=new dog("光头强");
		//可以new dog  因为dog已经实现了eat的代码实现具体
		//但是这里不能new animal   因为animal是抽象类 没有具体实现“吃”
		a.eat();
	}
}
~~~

创建和调用过程是：

```
创建Dog对象
    ↓
Dog构造方法通过super(name)调用Animal构造方法
    ↓
初始化名字为“光头强”
    ↓
Dog对象初始化完成，引用赋给a
    ↓
a.eat()执行Dog提供的实现
```

**父类构造方法被调用，并不代表单独创建了一个 `Animal` 对象。创建的仍然是一个 `Dog` 对象。**

```
public abstract void eat();
```
表示具体子类需要提供实现。
```
public void eat() {
}
```
则表示父类**已经提供了一个什么也不做的实现**，子类可以直接继承，不必重写。

**要修的**：

2. 笔记里写「int → double 是**高转低**」——反了。这是**小范围 → 大范围**的自动转换（低精度到高精度、不会丢信息），Java 叫「自动类型转换」；只有「大 → 小」才需要强转。
3. 有一处写 `public static void main()`——**标准入口必须是 `public static void main(String[] args)`**，少了参数 JVM 找不到入口。（终于知道为什么一定要加这个String[] args了）

## 接口interface
为什么要有接口
1. **一个类只能 `extends` 一个父类**。可现实里，"能付款"和"能退款"是两件独立的能力，凭啥必须塞进同一个父类？
2. **抽象类天生带"实现"和"状态"**（可以有成员变量、有构造方法）。但很多时候我只想喊一句"你必须会这个"，不想附带任何实现。
所以 Java 单独给了个类型：**接口**——它只描述「能做什么」，不描述「怎么做」，而且**一个类可以实现多个接口**。

> 抽象类 = 一份**带实现的模板**；接口 = 一份**纯行为契约**。

~~~
interface greeting{
	void sayhello();//声明有这个方法
}
~~~


~~~
class Cat implements greeting {
}//报错
~~~

cat不是抽象类   也没有重写greeting的抽象方法sayhello
**接口里每个没有方法体的方法，实现类都必须给出方法体**
如果把 `Cat` 写成 `abstract class Cat implements greeting`，它就能不实现——因为它本身也是抽象类，还没到“必须交作业”的时候

**要补上方法体**
~~~
class Cat implements greeting{
	@Override
	public void sayhello()
	{
		System.out.println("喵");
	}
}

~~~
1. **`public` 必须写。** 接口里的方法隐式就是 `public`，重写时不能缩小权限；写成默认权限会直接编译错误，这是高频坑。
2. **`@Override` 建议写。** 不是必须的，但写了编译器就帮你检查“是不是真重写了”；名字打错会立刻报错，而不是悄悄变成新方法。
3. **方法体里写什么是你的自由。** 接口只保证这个“方法存在”，不管你怎么实现。

**测试**
~~~
greeting g = new Cat();
g.sayhello();
~~~
能编译能运行    这里的g是接口类型
- **接口的作用就是规定“这个类型的变量能调用哪些方法”**。`greeting` 里写了 `sayhello()`，所以 `g.sayhello()` 编译器认可。
- **编译看左边**：左边声明类型 `greeting`，它里面有没有 `sayhello`？有 → 通过。
- **运行看右边**：右边实际对象是 `Cat`，执行谁的 `sayhello`？`Cat` 的 → 打印“喵”

真正编译不过的是这句：
```
Greeting g = new Greeting();   // ❌ 接口不能 new
```

|写法|结果|
|---|---|
|`Greeting g;`|✅ 合法，只是声明变量|
|`new Greeting()`|❌ 接口不能创建对象|
|`Greeting g = new Cat();`|✅ 多态：接口变量指向实现类对象|

 implements 是实现
 `class Cat implements greeting` 读作：
> `Cat` 这个类，声明自己实现 `greeting` 这个接口。

和extends不一样   extends是继承  extends后面可以跟类/接口
implements后面只能跟接口  表示承诺按照要求做  greeting接口  
可以写多个，逗号分隔
extends 继承的类只能一个  继承成员  

1. **一个类可以实现多个接口**：`class A implements X, Y, Z` ← 这是接口最大的价值，抽象类做不到。//或者换个说法  一个类  可以引用多种方法？
		
2. **接口之间不用 implements，用 `extends`**：`interface A extends B, C`（接口可以多继承接口）。
3. **implements 后面只能跟接口名**。`class A implements String` 是编译错误，因为 `String` 是类。

**和c++对应**
C++ 没有 `implements` 
```c++
class Cat : public Greeting { ... }   // 继承抽象基类，顺手把纯虚函数实现了
```
在 C++ 里，“继承”和“实现纯虚函数”是**同一个动作**。Java 把它拆成两个词：
- `extends` → 管类的继承
- `implements` → 管接口的实现



`interface Greeting` 里如果写了两个方法：
```
void sayhello();
void sayBye();
```
而 `Cat implements greeting` 只实现了 `sayhello()`，会怎样？
**编译根本过不去**
编译器会在 `class Cat implements Greeting` 这一行直接拦下，报的错和你上次看到的结构一样，只是换了方法名


| 写法                                                   | 结果                     |
| ---------------------------------------------------- | ---------------------- |
| `Cat` 实现了 sayhello 和 sayBye                          | ✅ 通过                   |
| `Cat` 只实现了 sayhello                                  | ❌ 编译错误（少交一份作业）         |
| `abstract class Cat implements greeting` 只写 sayhello | ✅ 通过；但 `new Cat()` 不行了 |

**`implements` 是“全包承诺”，不是“挑着做”。**
接口里几个抽象方法，实现类就得交几个方法实现。
- **抽象类**允许子类“只实现一部分”——没实现的，子类自己变抽象就行；
- **接口**不允许——普通类必须全交，交不齐就编译错误。

一个类能同时 `implements` 两个接口
```
class A implements X, Y { ... }
```
逗号隔开


**练习**
~~~
interface callable{

    void call();
}

interface camera{
    void photo();

}

class phone implements callable,camera{
    public void call(){
        System.out.println("11");
    }
    public void photo(){
        System.out.println("22");
    }
}

public class study01{
    public static void main(String[] args)
    {
        phone p=new phone();//造对象  p是phone类型  两个方法都有
        p.call();
        p.photo();//具体的实现   输出11和12
    }
}
~~~
**换个类型接收，就调不全了**
```
callable c = new phone();
c.call();       //  能编译：callable 里声明了 call()
// c.photo();   //  编译错误：callable 里没有 photo()
```
- **编译看左边**：左边是 `callable`，它只声明了 `call()` → `c.photo()` 编译不过；
- **运行看右边**：右边实际对象是 `phone`，`c.call()` 执行的是 `phone` 的 `call()` → 打印 11。

**接口里能不能写方法体？**

接口里的方法都没方法体。**Java 8 起，可以用default。**
```java
interface Callable {
    void call();                    // 抽象方法：必须交作业

    default void hangUp() {         // 默认方法：有方法体，可不交
        System.out.println("挂断");
    }
}
```
`default` 是个关键字，写在方法前面，然后正常写 `{ }`。
**现在 `class Phone implements Callable` 只写了 `call()`，不写 `hangUp()`，还能编译过吗？为什么？**

提示：回想刚才学的那条——「接口里几个抽象方法，就得交几个」。`hangUp` 算不算“要交的”？

**不算**
判断依据不是“是不是 `default`”，而是 **“有没有方法体”**：

|写法|有 `{}` 吗|实现类必须写吗|
|---|---|---|
|`void call();`|❌ 没有|✅ 必须交|
|`default void hangUp() { ... }`|✅ 有|❌ 不用交|

`default` 的意思就是“这个方法在接口里已经有实现路径了”，实现类**不写也能直接调用**。

 `Phone` 只写 `call()`，编译照样通过：
```java
class Phone implements Callable {
    public void call() { System.out.println("11"); }
}
```
`main` 里：
```
Phone p = new Phone();
p.call();      // 11
p.hangUp();    // 挂断   ← Phone 里没写这个方法，从接口“继承”来的
```

第二行能编译，正是因为 `hangUp()` 在 `Callable` 里已经声明过——还是「编译看左边」。

**c++对照**
C++ 的抽象基类本来就能同时放纯虚函数和普通成员函数：
```
virtual void call() = 0;      // 纯虚
void hangUp() { ... }         // 普通，子类白拿
```
Java 8 之前接口**做不到**这一点（里面一个方法体都不能有），所以才在 Java 8 补了 `default`。

**练习**
`Phone` 觉得“挂断”这两个字不够好，想改成打印「我先挂了」
```java
interface Callable {
    void call();                    // 抽象方法：必须交作业

	
    default void hangUp() {         // 默认方法：有方法体，可不交
        System.out.println("挂断");
    }
}

class Phone implements Callable {
    public void call() { System.out.println("11"); }
}

public class study01{
	public static void main(String[] args)
	{
		Phone p=new Phone();
		p.call();
		
		@Override
		public void hangup(){
			System.out.println("我先挂了");
		}
	}

}
```

`default` 方法**可以被重写**，重写时一样建议加 `@Override`。重写之后，就算你用 `Callable c = new Phone(); c.hangUp();` 调用，走的也是 `Phone` 的版本——多态在接口这里同样成立

## `default` 到底为什么存在？
**接口加新方法，会迫使一批实现类跟着修改**

假设 `Callable` 已经有一百个实现类。现在产品说“所有能打电话的东西都要能挂断”，你要给接口加一个 `hangUp()`：
- 如果只能写**抽象方法** → 那一百个类全部编译报错，得挨个补；
- 写成 **`default`** → 只改接口一处，一百个类一行不动，全都能用。
所以 `default` 是给**已经发布出去的接口**留的“扩展补丁”

**接口和抽象类**
抽象类：可以随便存成员变量  可以有构造方法   可以有具体方法  一个类能接一个抽象类
接口：只能存public static final常量 没有构造方法   只有default static private的具体方法
一个类可以接多个接口
抽象类是既有状态又有实现   接口只有声明行为


当几个类要共享同一套字段和代码，都用name eat------用抽象类
没有共同父类，只有共同行为    不相关的类要执行同一个行为----比如都要吃，睡觉-----用接口
既要共享实现   又要留拓展的点-------用抽象类做框架  +  接口来补充

### 接口里的“变量”是常量       
```
interface Payable {
    String CURRENCY = "CNY";//有点像c的宏定义
}
```
这三个修饰符**全省略也成立**，编译器自动补成：
```
public static final String CURRENCY = "CNY";
```
两个后果：
- **必须当场初始化**，`String CURRENCY;` 编译错误；
- 访问写 `Payable.CURRENCY`（通过对象访问也行，但没人这么写）。

对比 C 的 `#define CNY "CNY"`：那是预处理阶段的**文本替换**，没有类型；接口常量是有类型的真变量，编译器会检查你把它用在哪。

**接口可以有static方法**
~~~java
interface Payable{
	static void info(){
		System.out.println("支付接口");
	}
}
~~~
只能通过接口名调用   Payable.info();

**default和static  两种有方法体**
default void hangup()     用对象调用   p.hangup()      可以多态，能被重写
static void info()     用接口名调  Payable.info()        不可以有多态   和类的static一样  


**测试**
~~~java
interface USB{
    void work();
}
class Keyboard implements USB{

## 内部类
内部类是写在一个类里面的类--好像说了和没说一样
~~~
class Outer {                 // 外部类
    class Inner {             // 成员内部类
        void hi()
        {
	         System.out.println("hi");
		}
    }
}
~~~
要创建inner
~~~
Outer.Inner in=new Outer().new Inner();
~~~
`Inner` 不是独立存在的类，它是 `Outer` 的一部分，必须先有一个 `Outer` 对象，`Inner` 才有依赖。

C++ 里写的嵌套类：
```
class Outer {
public:
    class Inner {  };
};
Outer::Inner in;        // C++ 只要写类型，不需要 Outer 对象
```
C++ 嵌套类**只是名字被包了一层**，跟外部类对象没关系；Java 的**成员内部类**是真“绑”在外部对象上的



在 `Inner` 的 `hi()` 里面，能**直接**访问 `Outer` 的成员变量，不用写 `outer.xxx`
**每个 `Inner` 对象内部都隐式带着一个“外部对象”的引用**，Java 里叫 `Outer.this`。
所以 `count` 其实等价于 `Outer.this.count`。这也是为什么必须先 `new Outer()` 才能 `new Inner()`——那个引用得有个着落。
```
class Outer {
    int count = 10;
    class Inner {
        void hi() {
            System.out.println(count);   // 这行行不行？
        }
    }
}
```

**变量同名**
~~~
class Outer {
    int count = 10;

    class Inner {
        int count = 20;

        void hi() {
            System.out.println(count);             // 20  ← 就近，先找自己的
            System.out.println(Outer.this.count);  // 10  ← 点名要外部的
        }
    }
}
~~~

|写法|拿到谁|
|---|---|
|`count`|最近的：Inner 自己的|
|`this.count`|Inner 自己的（同一个）|
|`Outer.this.count`|外面那个对象的|

 **C++ 对比**
~~~
class Outer {
	public:
	    int count = 10;
	    class Inner {
	        void hi() {
	            // 这里写 count  → 编译错误！C++ 嵌套类没有“外部对象”这个概念
	    }
	};
};
~~~
C++ 的嵌套类**只是个名字被包起来的普通类**，跟 `Outer` 的对象毫无关系，想用 `Outer` 的数据必须自己传进来（`Outer& o` 或指针）。
Java 的成员内部类反过来：**它天生绑着一个外部对象**
